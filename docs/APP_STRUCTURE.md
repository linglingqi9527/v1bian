# 应用结构

「辩了么」不是长网页，也不是后台管理系统。它应像一个固定尺寸的桌面应用窗口，整个产品被装在一个明确的方块容器里。

## 总体框架

核心结构：

外部背景 -> 居中的应用窗口 -> 左侧导航栏 + 右侧主操作区

应用窗口本身应像一个完整系统，而不是页面上散落的模块。

## 外层页面

外层页面只负责承载产品，不承载内容滚动。

要求：

- 页面整体居中显示应用窗口。
- 外部背景不承担业务内容。
- 外部页面不应出现主要业务滚动。
- 视觉重心应集中在应用窗口内。

## 应用窗口

应用窗口是固定比例、固定边界的方块型容器。

要求：

- 左侧导航和右侧主操作区属于同一个大框。
- 左右两边高度一致。
- 外框边界明确。
- 左右之间用分隔线连接，而不是两个分离卡片。
- 主体窗口有最大高度，接近视口高度，但不无限拉伸。
- 主体窗口有最大宽度，避免大屏上内容被拉得过散。
- 内容少时，窗口仍保持完整形态。
- 内容多时，只在窗口内部滚动。

## 滚动规则

桌面端：

- 外部页面不滚动。
- 左侧导航默认不滚动；如果内容溢出，只在自身内部滚动。
- 右侧主操作区内部滚动。
- 看比赛、赛评库、赛评编辑、训练库都在同一个主操作区内切换。
- 用户滚动时，应感觉是在 app 的内容区域里滚，而不是在浏览器页面里滚。
- 业务滚动条可以隐藏，但滚动能力要保留。

## 页面入口原则

主要对象的大标题、主按钮、列表项都应成为直接入口。

- 看比赛页：点击辩题进入观看或比赛详情。
- 赛评库：点击赛评标题进入赛评编辑或详情。
- 训练库：点击训练标题进入训练详情。
- 左侧近期赛评：点击标题进入赛评。
- 左侧近期训练：点击标题进入训练。

用户不应该每次都寻找小按钮。最自然的文本对象应能直接进入下一步。

## 当前页面分层

当前项目已建立以下页面层：

- `HomePage.jsx`
- `MatchesPage.jsx`
- `MatchDetailPage.jsx`
- `ReviewsPage.jsx`
- `ReviewDetailPage.jsx`
- `ReviewEditorPage.jsx`
- `TrainingsPage.jsx`
- `TrainingCreatePage.jsx`
- `TrainingDetailPage.jsx`
- `ProfilePage.jsx`

页面层负责组合业务场景。通用布局、导航、手绘组件、按钮、标签、卡片应优先使用 `design-system` 中的组件。

## 当前结构重点

当前阶段的重点不是增加页面功能，而是让以下结构稳定：

- `src/app` 负责应用入口、路由和 providers。
- `src/pages` 负责页面级组合。
- `src/features` 负责业务模块能力。
- `src/design-system` 负责视觉组件、布局组件、手绘效果和 tokens。
- `src/assets` 负责静态素材。
- `src/data` 负责 demo 数据。
- `src/models` 负责数据模型。
- `src/hooks` 负责通用 React hooks。
- `src/styles` 负责全局样式、主题和手绘基础样式。
