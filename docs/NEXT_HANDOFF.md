# 新对话交接说明

这份文件给下一轮 Codex / AI 先读。它不是完整 README，只记录当前最容易误判的状态和边界。请先读 `AGENTS.md`，再读本文件。

## 一、视觉与动画现状

当前已经比较满意、不要轻易重做：

- 固定 app shell：外部背景、居中应用窗口、左侧导航、右侧主操作区，这个方向保留。
- 外围大边框：当前手绘感和整体框架效果满意，不要推倒重做。
- 看比赛页面的小边框：比赛卡片、筛选小框、状态标签等小面积边框效果目前可保留。
- 状态标签涂鸦：`未看 / 已看 / 待评 / 已练` 这类小标签的 hachure 手绘填充效果基本满意。
- 收藏书签：这是目前最满意的手绘元素。书签形状、黑色边框、黄色 hachure 填充不要随便换方案。
- 看比赛交互里的选中态：筛选、已看、收藏等状态联动和视觉方向已经基本通过。

当前还不满意、后续可小步调整：

- 大面积 hachure 填充还不够真实，尤其是较大的导航 active、观看比赛按钮等，可能需要继续调线条粗细、角度、密度和边框压层。
- 看比赛卡片右侧三个操作按钮的图标、文字位置和对齐仍需调整。
- 比赛卡片右侧靠近收藏区域的小竖杠需要重新设计。
- 左侧栏整体视觉还没有真正收口，只是临时达到可用。
- 页面里还有很多小字、密度、层级需要继续打磨。

重要边界：

- 不要恢复 `RoughSelectionLayer`。
- 不要在页面或 feature 中直接 import `roughjs`。
- 手绘填充、边框、动画优先从 `design-system/handdrawn` 和 `SketchButton / SketchTag / SketchCard / SketchNavLink` 进入。
- 不要为了一个页面效果写一堆不可复用的实验 CSS。可以小实验，但要命名清楚，方便迁移。

## 三、接下来两个功能的范围

### 功能 1：写赛评

要做什么：

- 主动进入“写赛评”时，先展示历史赛评列表。当前已完成。
- 从比赛卡片点击“打开赛评”时，携带 `matchId` 进入对应比赛的赛评编辑页。当前已完成。
- 一个比赛只能对应一个赛评。当前已通过 `reviewService.saveReviewForMatch` 约束。
- 保存赛评后，比赛卡片的 `reviewId` 点亮“已评”状态。当前通过 service 回写。
- 赛评评价的是比赛，不评价自己。

不做什么：

- 不接后端。
- 不做登录系统。
- 不做 AI 生成赛评。
- 不把赛评正文放进 `src/assets`。
- 不重做看比赛页面视觉。

入口在哪里：

- 左侧导航“写赛评”进入赛评列表。
- 比赛卡片“打开赛评”进入该比赛对应赛评编辑。
- 赛评列表“训练”按钮只是预留跳转口，当前进入训练创建占位页，后续再打通训练记录。

数据先用什么：

- 先使用本地数据层，继续预留 `userId: "demo-user"`。
- 可以先用 localStorage，后续再升级 IndexedDB。
- 数据结构要为未来本地文件导出保留空间。

当前文件收口：

- `src/features/reviews/components/ReviewListRow.jsx` 管赛评列表行。
- `src/features/reviews/components/ReviewPriorityPicker.jsx` 管重要性颜色选择。
- `src/features/reviews/components/ReviewsList.css` 管赛评列表样式。
- `src/features/reviews/reviewListUtils.js` 管列表拼装、搜索和筛选。
- `src/pages/ReviewsPage.jsx` 保持页面组合，不再直接拼 match/training 数据。

### 功能 2：做训练

要做什么：

- 主动进入“做训练”时，先展示训练列表。
- 从比赛卡片点击“开始训练”时，携带 `matchId` 进入训练创建流程。
- 一场比赛可以对应多次训练。
- 训练记录保存后，把新训练 id 加入比赛的 `trainingIds`，卡片显示 `已练 N`。
- 训练备注评价自己，不要和赛评内容混在一起。

不做什么：

- 不接真实录音/录像后端。
- 不做云同步。
- 不做 AI 评价。
- 不在录制结束后自动保存。
- 不把音频、视频、训练备注放进 `src/assets`。

入口在哪里：

- 左侧导航“做训练”进入训练列表。
- 比赛卡片“开始训练”进入该比赛关联训练流程。
- 赛评页后续也可以有“从这篇赛评开始训练”的入口，但不要一次性扩太大。

数据先用什么：

- 先使用本地保存，继续预留 `userId: "demo-user"`。
- 训练数据要和赛评数据分开。
- 录音/录像文件未来要本地保存，不进 Git、不进 `src/assets`。

## 四、给下一轮 Codex 的工作方式

- 先做结构检查，再做小步计划。
- 不要同时改视觉、功能、爬虫、数据模型。
- 当前最应该回到前端框架和页面结构收口。
- 优先减少 demo 遗留和重复样式，而不是新增大功能。
- 如果要改通用组件，先确认它会影响哪些页面。
- 每次修改后运行 `npm.cmd run build`。
