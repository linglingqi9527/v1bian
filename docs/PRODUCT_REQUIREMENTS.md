# 产品需求

「辩了么」是面向辩手的辩论复盘与训练工作台。产品以“比赛”为核心对象，把看比赛、写赛评、做训练串成一个可持续使用的复盘闭环。

## 核心闭环

看比赛 -> 标记已看 / 写赛评 -> 进入赛评 -> 从赛评开始训练 -> 录音或录像 -> 预览 -> 重录或保存 -> 生成训练记录 -> 回到赛评页查看关联训练。

## 核心模块

### 看比赛

看比赛模块负责检索比赛、进入比赛资料、建立用户与比赛之间的关系。

应支持的核心信息：

- 辩题
- 学校 / 队伍
- 辩手
- 比赛日期
- BV 号
- B 站链接
- 用户是否已看
- 用户是否已有赛评
- 关联训练次数

看比赛页的比赛卡片应以辩题为主标题。场次信息作为次级信息展示，学校、辩手、日期、BV 号辅助用户判断是否是目标比赛。

### 写赛评

写赛评模块分为赛评库和赛评编辑。

用户主动进入“写赛评”时，先进入赛评列表，不能直接进入编辑器。赛评库用于快速找到过去的复盘，应支持按最近编辑、已完成、草稿、已训练等状态查看。

用户从比赛详情或比赛卡片点击“写赛评”时，可以直接进入该比赛对应的赛评编辑页。

产品规则：

- 一个比赛对应一个赛评。
- 赛评记录用户如何理解和评价这场比赛。
- 赛评内容不存放训练备注。
- 赛评页应能看到该比赛关联的训练记录。

### 做训练

做训练模块分为训练库、训练创建、训练详情。

用户主动进入“做训练”时，先进入训练列表，不能直接进入录制页。从赛评页或比赛页发起训练时，可以自动关联当前比赛或当前赛评。

训练录制流程：

1. 开始录制
2. 结束录制
3. 进入预览
4. 用户选择重录或保存
5. 只有点击“保存训练”后才生成训练记录

产品规则：

- 一个比赛可以对应多个训练。
- 训练备注评价自己的表达、节奏、内容和改进方向。
- 训练备注和赛评正文必须分离。
- 训练详情页展示本次训练的录音、录像、陈词稿、训练备注和训练复盘。

### 我的

“我的”模块用于承载个人设置、数据统计、导入导出入口和后续账号能力。当前阶段只保留基础入口，不接登录系统。

### 后续资料包

后续可加入资料包能力，用于沉淀比赛资料、备赛笔记、表达素材和自定义分类。资料包仍应围绕比赛、赛评和训练建立关联，避免变成孤立文件管理器。

## 数据关系

- 比赛是核心对象。
- 一个比赛对应一个赛评。
- 一个比赛可以对应多个训练。
- 赛评与训练都需要预留 `userId`。
- 当前 demo 阶段统一使用 `demo-user`。

## 当前不做

当前阶段不接后端、不做登录、不接真实 B 站数据、不做真实爬虫、不做 AI。当前重点是把产品流程、页面结构、design-system 和本地 demo 数据关系整理清楚。
